Privacy Policy for TextSnap

Application: com.jverse.textsnap 100% Offline & Zero Data Collection Updated: October 10, 2026 Developer: jaimin229

TextSnap ("we", "our", or "us") is dedicated to protecting your privacy. This Privacy Policy explains how TextSnap operates as a 100% offline, privacy-first mobile application for Android developed by Jaimin Prajapati (operating as jaimin229 / JVerse).

TextSnap is engineered around one core principle: your photos, your extracted text, and your search queries never leave your device.

1. 100% Offline Architecture & Zero Network Access

TextSnap is strictly a local offline utility. We do not collect, store, transmit, process, share, or sell any of your personal data, images, extracted text, search queries, or device information to external servers, cloud providers, or third parties.

  • Zero Network Permission: TextSnap explicitly removes network capabilities at compile time by declaring tools:node="remove" for android.permission.INTERNET and android.permission.ACCESS_NETWORK_STATE in its Android manifest. It is physically and architecturally impossible for the application to transmit data over the internet.
  • Zero Server Infrastructure: We do not operate, host, or communicate with any cloud servers, databases, application programming interfaces (APIs), or telemetry collectors.
  • Zero Remote Storage: All document databases, full-text search indexes (SQLite/Room FTS4), search history entries, and encrypted vault files reside exclusively within your device's sandboxed local storage (/data/data/com.jverse.textsnap/).

2. On-Device Machine Learning (ML Kit OCR)

TextSnap performs Optical Character Recognition (OCR) locally using Google's on-device ML Kit text recognition runtime:

  • Bundled Model Weights: Language recognition models (Latin, Devanagari, and Chinese scripts) are bundled directly inside the local application binary.
  • Local Hardware Inference: All image analysis, bitmap decoding, and character recognition calculations execute 100% locally on your device's CPU, GPU, or Neural Processing Unit (NPU).
  • Zero Cloud Transmission: Images and extracted text strings are never uploaded to Google Cloud Vision or any other remote service. ML Kit runs completely isolated from the internet.
  • Ephemeral RAM Processing: Image frames loaded into memory for scanning are processed ephemerally in volatile RAM. Extracted text is stored directly into your local on-device SQLite database and immediately cleared from active process memory.

3. Hardware-Backed Encryption & Vault Security

TextSnap includes a private Vault feature designed to protect sensitive images and extracted information:

  • Hardware-Backed AES-256-GCM: When you place an image in the Vault, the file is encrypted locally using the Advanced Encryption Standard with a 256-bit key in Galois/Counter Mode (AES-256-GCM).
  • Android Keystore System: Cryptographic keys are generated and securely stored within the Android Keystore, backed by your device's hardware security module (Trusted Execution Environment - TEE, or StrongBox Keymaster). The master encryption keys never leave the hardware boundary and are inaccessible to us, other applications, or the operating system.
  • Biometric Authentication (USE_BIOMETRIC): Access to your Vault is gated via Android's native BiometricPrompt framework (BIOMETRIC_STRONG or DEVICE_CREDENTIAL). TextSnap never handles, stores, or accesses your biometric templates (fingerprint, facial data) or device PIN/passcode. Authentication is verified strictly by the Android operating system.
  • Screen Capture Protection: All Vault screens enforce Android's FLAG_SECURE window attribute, preventing unauthorized screenshots, screen recording, and system task switcher previews.
  • Encrypted Local Backups: Database backups exported via TextSnap (.tsnap files) are encrypted with AES-256-GCM and saved only to user-selected local device locations.

4. Zero Analytics, Zero Tracking, Zero Cookies

  • No Third-Party Analytics: TextSnap does not integrate Google Analytics, Firebase Analytics, Mixpanel, Amplitude, or any other telemetry libraries.
  • No Advertising SDKs: TextSnap is a direct-purchase, ad-free application. It contains no ad mediation SDKs (such as AdMob or Unity Ads) and displays no advertising.
  • No Crash Telemetry SDKs: We do not embed Firebase Crashlytics, Sentry, or Bugsnag. Crash traces are not transmitted over the network.
  • No Tracking Identifiers: TextSnap does not access, collect, or log Google Advertising IDs (AAID), Android IDs, App Set IDs, MAC addresses, IMEI numbers, or device fingerprints.
  • Zero Website Cookies / Trackers: This static website hosted on GitHub Pages uses zero cookies, zero web beacons, and zero third-party tracking scripts.

7. Google Play In-App Updates & Network Accounting Transparency

TextSnap integrates Google Play's official In-App Update API (com.google.android.play:app-update) to ensure you always have access to the latest security enhancements:

  • Local IPC Communication Only: Update checks communicate strictly via local Android IPC Binder directly with the Google Play Store client application (com.android.vending). TextSnap does not request or possess android.permission.INTERNET.
  • Negligible Network Accounting Footprint: If an advanced user inspects device settings (Settings > Apps > TextSnap > Mobile data) and observes a nominal data usage footprint (typically between 5 KB to 25 KB), this represents operating-system-level network accounting (Linux kernel eBPF / xt_qtaguid) attributed to the calling UID during the Google Play Store client's version-handshake check and Play Protect security scans.
  • Zero Data Transmission: At no point does TextSnap open network sockets or transmit any user photographs, extracted OCR text, search queries, or personal data. Zero bytes of user content ever leave your physical device.
